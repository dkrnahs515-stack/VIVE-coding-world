# 코딩 월드 — 기억의 조각 설계

## 목적

VIVE Coding World를 방문한 사람이 2026년 강서청소년회관 바이브 코딩 참가자들의 4회기 활동 과정과 제작 경험을 짧은 웹게임 형태로 탐색한다. 참가자 답변은 구현 시 비워 두고, 운영자가 추후 데이터 파일 한곳에서 직접 입력한다.

## 공개 정보 원칙

- 참가자는 실제 이름 대신 닉네임으로만 표시한다.
- 정확한 나이와 성별은 수집하거나 공개하지 않는다.
- 필요할 때만 넓은 학교급(`초등학생`, `중학생`, `고등학생`)을 선택 항목으로 사용한다.
- 참가자 및 만 14세 미만 참가자의 법정대리인 동의를 받은 내용만 게시한다.
- 자유서술에 학교명, 반, 연락처, 계정명 등 개인을 추정할 수 있는 정보가 포함되지 않도록 게시 전에 확인한다.

## 게임 경험

게임 이름은 **코딩 월드 — 기억의 조각**이다. 방문자는 3~5분 동안 네 개의 구역을 순서대로 둘러보며 참가자 카드 형태의 기억 조각을 수집한다.

1. 시작 화면에서 게임 목적과 조작 방법을 확인한다.
2. 네 구역 중 하나를 선택한다.
3. 구역 안의 참가자 기억 조각을 선택해 회고 카드를 읽는다.
4. 읽은 조각은 수집 현황에 반영된다.
5. 모든 구역을 방문하면 마지막 메시지 화면이 열린다.
6. 마지막 화면에서 메인 아케이드 또는 참가자 제작 게임으로 이동할 수 있다.

참가자 내용이 아직 입력되지 않은 초기 상태에서도 게임이 깨지지 않아야 한다. 빈 구역에는 `아직 등록된 기억의 조각이 없습니다` 안내와 데이터 입력 위치를 표시한다.

## 네 개의 구역

| 구역 | 회고 주제 | 대표 질문 |
|---|---|---|
| 아이디어 광장 | 처음의 기대와 아이디어 | 어떤 게임이나 기능을 만들고 싶었나요? |
| 제작 공방 | 제작 과정의 즐거움 | 만들면서 가장 즐거웠던 순간은 무엇인가요? |
| 오류의 미로 | 고민과 문제 해결 | 가장 어려웠던 문제와 해결 방법은 무엇인가요? |
| 공유의 별빛길 | 성장과 전달하고 싶은 말 | 배운 점과 방문자에게 전하고 싶은 말은 무엇인가요? |

## 화면 구성

### 시작 화면

- 게임 제목과 한 문장 소개
- `기억 탐험 시작` 버튼
- 개인정보를 최소화해 게시한다는 짧은 안내
- `메인 아케이드로 나가기` 링크

### 탐험 화면

- 상단: 현재 구역명, 수집한 조각 수, 메인 복귀 버튼
- 중앙: 네 구역 카드와 각 구역의 기억 조각 카드
- 하단: 이전/다음 구역 이동 및 전체 진행 상황
- 모바일에서는 한 열, 넓은 화면에서는 두 열 이상의 반응형 카드 배치

### 기억 카드 모달

- 닉네임
- 선택 입력인 학교급
- 만든 게임 또는 기능
- 구역별 회고 답변
- 참가자가 고른 이모지와 강조 색상
- 닫기 버튼과 키보드 `Esc` 지원

### 엔딩 화면

- 네 구역 방문 완료 메시지
- 참가자들의 마지막 한마디 카드
- `참가자 게임 플레이하기`와 `메인 아케이드로 돌아가기` 버튼

## 데이터 구조

참가자 정보는 `games/memory_fragments/participants.js` 한 파일에서 관리한다. 구현 직후에는 아래 필드를 모두 빈 문자열로 둔 템플릿 객체만 제공하며 화면에는 실제 참가자 정보가 표시되지 않는다.

```js
{
  nickname: '',
  schoolLevel: '',
  gameTitle: '',
  gameUrl: '',
  emoji: '',
  color: '',
  idea: '',
  joy: '',
  challenge: '',
  solution: '',
  learning: '',
  message: ''
}
```

운영자는 템플릿 객체를 복사해 참가자 수만큼 배열에 추가한다. `nickname`이 빈 항목은 미등록 데이터로 처리해 공개 카드에서 제외한다.

## 기술 구성

- 기존 프로젝트와 동일한 순수 HTML, CSS, JavaScript로 구현한다.
- 새 폴더는 `games/memory_fragments/`로 만들고 `index.html`, `style.css`, `participants.js`, `main.js`로 역할을 나눈다.
- 별도 빌드 과정이나 외부 프레임워크 없이 GitHub Pages에서 바로 실행한다.
- 진행 상태는 브라우저 메모리에서만 관리한다. 참가자 개인정보와 방문 기록은 `localStorage`나 서버에 저장하지 않는다.
- 메인 `index.html`에 13번째 게임 카드를 추가하고 README의 게임 목록과 폴더 구조를 갱신한다.

## 상태와 예외 처리

- 빈 데이터: 안내용 빈 상태를 표시하고 네 구역 탐색은 가능하게 유지한다.
- 일부 답변 누락: 값이 있는 항목만 카드에 표시한다.
- 잘못된 색상 또는 URL: 기본 네온 색상과 안전한 상대/HTTPS 링크를 사용한다.
- 모든 조각 수집 여부와 별개로 메인 아케이드 복귀는 항상 가능해야 한다.
- 스크립트를 불러오지 못하면 사용자에게 새로고침 안내를 표시한다.

## 접근성 및 반응형

- 모든 카드와 버튼은 키보드로 접근할 수 있게 한다.
- 선택 상태는 색상뿐 아니라 텍스트와 아이콘으로도 구분한다.
- 모달은 제목 연결, 닫기 버튼, 바깥 영역 클릭, `Esc` 닫기를 제공한다.
- 작은 화면에서 가로 스크롤이 생기지 않도록 하고 터치 영역은 최소 44px로 유지한다.
- 움직임 감소 설정을 사용하는 환경에서는 장식 애니메이션을 줄인다.

## 검증 기준

- 빈 참가자 데이터로 시작·구역 이동·엔딩·메인 복귀가 모두 동작한다.
- 유효한 테스트 참가자 데이터를 임시로 넣으면 구역별 카드 내용과 수집 수가 정확히 갱신된다.
- 닉네임이 빈 항목과 빈 답변은 공개 화면에 노출되지 않는다.
- 모바일과 데스크톱에서 카드, 모달, 버튼이 화면 밖으로 넘치지 않는다.
- 메인 아케이드 카드와 README 링크가 실제 게임 경로를 가리킨다.

## 범위 제외

방문자 댓글 입력, 서버 저장, 로그인, 실시간 랭킹, 정확한 나이·성별 공개, 관리자 화면은 이번 구현에 포함하지 않는다. 참가자 답변은 저장소의 데이터 파일을 직접 수정해 게시한다.
